## Производительность

### 🔴 Критично

**PERF-01: RAG embeddings хранятся как TEXT, cosine similarity в Node.js**
- **Файл:** `server/services/rag-retrieval.ts`, `shared/schema.ts` (поле `embedding TEXT`)
- **Проблема:** При каждом AI-запросе загружаются ВСЕ чанки тенанта из PostgreSQL. Cosine similarity вычисляется в Node.js для каждого чанка. При 1000+ чанках — медленно и memory-intensive.
- **Решение:** Мигрировать на `pgvector` extension.
  ```sql
  CREATE EXTENSION IF NOT EXISTS vector;
  ALTER TABLE rag_chunks ADD COLUMN embedding_vector vector(1536);
  CREATE INDEX ON rag_chunks USING ivfflat (embedding_vector vector_cosine_ops);
  ```
  Изменить `rag-retrieval.ts`: заменить in-memory cosine на `<=>` оператор.
- **Эффект:** 10–100x ускорение при >500 чанков
- **Сложность:** Средняя (одна миграция + изменение retrieval)

### ⚠️ Требует внимания

**PERF-02: Self-check — отдельный GPT-вызов (+~300мс, +~$0.001)**
- **Файл:** `server/services/decision-engine.ts` (функция `performSelfCheck`)
- **Проблема:** Каждая генерация AI-подсказки делает 2 GPT-вызова
- **Рекомендация:** Объединить self-check в основной промпт как дополнительный JSON-блок
- **Сложность:** Средняя

**PERF-03: Нет кэширования похожих запросов**
- **Файл:** `server/services/decision-engine.ts`
- **Проблема:** Два похожих вопроса ("цена Civic", "сколько стоит Honda Civic") → два полных GPT-вызова
- **Рекомендация:** Semantic cache: хранить последние N embedding+ответов, при similarity > threshold → вернуть кэшированный ответ
- **Сложность:** Средняя

**PERF-04: Нет пагинации в списке диалогов (frontend)**
- **Файл:** `client/src/pages/conversations.tsx`
- **Проблема:** При большом количестве диалогов всё загружается сразу
- **Рекомендация:** Cursor-based pagination или virtual scroll
- **Сложность:** Средняя

## Надёжность

### ⚠️ Требует внимания

**REL-01: WhatsApp-сессии хранятся на диске**
- **Файл:** `server/services/whatsapp-personal-adapter.ts` (AUTH_DIR = `./auth_sessions/`)
- **Проблема:** При деплое нового сервера или Docker-контейнера все WhatsApp-сессии теряются. Клиентам нужно заново сканировать QR.
- **Рекомендация:** Сохранять Baileys auth state в PostgreSQL (аналогично telegram_sessions)
- **Сложность:** Средняя

**REL-02: CryptoBot webhook — нет retry/idempotency**
- **Файл:** `server/services/cryptobot-billing.ts` (функция `handleWebhookEvent`)
- **Проблема:** Если сервер упал в момент получения webhook `invoice_paid`, подписка не активируется. Нет защиты от дублирования webhook.
- **Рекомендация:**
  1. Проверять `crypto_invoice_id` перед обновлением (идемпотентность)
  2. Cron-джоб: периодически проверять статус pending invoice через CryptoBot API
- **Сложность:** Средняя

**REL-03: Нет уведомлений об истечении подписки**
- **Файл:** `server/services/cryptobot-billing.ts`
- **Проблема:** Пользователь узнаёт об истечении подписки только когда получает 402/paywall
- **Рекомендация:** Email за 7 и 1 день до `current_period_end` через email-provider.ts
- **Сложность:** Низкая
